## Background and evidence

The fixed SDK baseline `a2e6a536171f33183ec579327cdd6566b77f7c08` deliberately reconstructs display Events without remote metadata. SkyEyes now distinguishes approved final-answer requests from tool narration in its server-owned model adapter. Dropping this purpose prevents downstream HTTP and UI consumers from safely displaying actual answer deltas. Allowing arbitrary Part metadata or all remote metadata would weaken existing isolation.

The owning business design is `/Users/bytedance/Workspaces/VolcengineProjects/SkyEyes.worktrees/quality-20261022/docs/project/final-answer-stream-design-20261024.md`. The model adapter, SDK, HTTP and page now have frozen offline red/green evidence. Real-provider acceptance and the final released artifact remain incomplete.

## Goals, scope and scenarios

Preserve only the explicit, validated final-answer display label across `CustomerAdkEventStream`. This is a display contract, not research authorization or a new authentication mechanism. The configured Host owns approval and source provenance. No public Python signature, dependency, model, tool dispatch, Part schema, user input, session key or persistence schema changes.

- FR-1: Given approved Host text deltas, projection retains `customMetadata.skyeyes_output_purpose={"version":1,"purpose":"final_answer"}` using local Event identity; consumers see deltas before Host completion.
- FR-2: Other remote metadata stays excluded. Snake/camel aliases are supported without ambiguity. The reserved object has exactly two keys, an integer (not bool/float) version 1 and the exact purpose enum. Malformed reserved values fail with `invalid_output_purpose`, containing no input values.
- FR-3: The label is accepted only on model text Events without thoughts, tools, user echoes or contentless output. It cannot authorize tool execution or change local identity/state.
- FR-4: Complete answer publication still waits for dispatcher success/ACK/cleanup; cancel/error/missing-final retain their existing failure semantics. Metadata does not synthesize final text or replay deltas.

## Design and contract impact

Add one private metadata projection helper to `events.py`. Read the existing top-level custom-metadata aliases and construct a fresh whitelist object. Validate label/content compatibility before constructing the local Event. No provider/input-controlled metadata is promoted by SDK inference. The business Host must create the label only after its own approval checks.

Runtime journaling and ADK serialization already preserve local Event custom metadata. Test the real dispatcher/Event stream with synthetic local transports; preserve existing arbitrary-metadata exclusion assertions. Queue capacity, deadlines, cancellation and cleanup ownership remain unchanged. Extra validation is constant work per Event under existing 1 MiB/4096-event bounds. No additional network calls or persistent state.

CON-2 gains a narrowly specified display-only exception; CON-7 owns the label contract. Other component contracts have no impact: channel framing, tools and session ownership remain unchanged. An old SDK ignores the label; downstream business deployment requires a separately built and verified new pinned artifact.
